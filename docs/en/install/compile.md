If the compilation environment can access the network, refer to [Online Compilation](#online-compilation). The build script will automatically download third-party software online. Otherwise, refer to [Offline Compilation](#offline-compilation) to manually download third-party software.

After the open-source third-party software is ready, use one of the following compilation methods as needed:

- **Custom operator package**:

  The package generated by compiling selected operators is called a custom operator package. It applies to the CANN package in **mount** form and does not change the original package content. The generated custom operator package has a higher priority than the original CANN package. This package supports calling AI Core and AI CPU operators through aclnn and graph mode.

- **ops-cv package**:

  The package generated by compiling the entire project is called the ops-cv package. It can **completely replace** the corresponding part of the CANN package. The package supports calling AI Core operators through aclnn and graph mode.

- **ops-cv static library**:

  > Note: If you need to **perform secondary release based on this project** and have **requirements on the software package size**, it is recommended to use static library compilation. This library can be linked to the application development program and only retains the operators required by the business, thereby implementing minimal software deployment.

  The entire project is compiled into a static library file, including libcann_cv_static.a and aclnn API header files. The package only supports calling AI Core operators through aclnn.

## Online Compilation

If compilation is performed in an environment with internet access, third-party dependencies will automatically be installed during compilation, and no manual installation is required. The source code compilation and deployment commands in different scenarios are as follows:

### Custom Operator Package

1. **Compile the custom operator package**

    Enter the project root directory and execute the following compile command:

    ```bash
    bash build.sh --pkg --soc=${soc_version} [--vendor_name=${vendor_name}] [--ops=${op_list}] [-j${n}]
    # Taking GridSample operator compilation as an example
    # bash build.sh --pkg --soc=ascend910b --ops=grid_sample -j16
    # Compile the user operators in the experimental contribution directory (taking the GridSample operator as an example; use the actual contributed operator during compilation)
    # bash build.sh --pkg --experimental --soc=ascend910b --ops=grid_sample -j16
    ```

    - --soc: \$\{soc\_version\} indicates the NPU model. Atlas A2 products use "ascend910b" (default), Atlas A3 products use "ascend910_93", and Ascend 950PR&950DT products use "ascend950".
    - --vendor_name (optional): \$\{vendor\_name\} indicates the name of the custom operator package to build. The default name is custom.
    - --ops (optional): \$\{op\_list\} indicates the operators to be compiled. If not specified, all operators are compiled by default. The format is "grid_sample,iou_v2,...", with multiple operators separated by English commas ",".
    - --experimental (optional): Indicates compiling the operators that the user stores under the experimental contrib directory.
    - -j (optional): Specifies the number of compilation threads to speed up compilation.

    If neither \$\{vendor\_name\} nor \$\{op\_list\} is passed in, the ops-cv package is compiled. To compile the custom operator package of all operators, pass in \$\{vendor\_name\}. When the following information is prompted, the compilation is successful.

    ```bash
    Self-extractable archive "cann-ops-cv-${vendor_name}-linux.${arch}.run" successfully created.
    ```

    After successful compilation, the run package is stored in the build_out directory under the project root directory.

2. **Install the custom operator package**

    ```bash
    ./build_out/cann-ops-cv-${vendor_name}-linux.${arch}.run
    ```

    The default installation path of the custom operator package is ```${ASCEND_HOME_PATH}/opp/vendors```. \$\{ASCEND\_HOME\_PATH\} is configured through an environment variable and indicates the installation path of the CANN toolkit package, generally \$\{install\_path\}/cann.

    > Note: You can define the operator package installation directory by configuring the --install-path=\$\{install\_path\} parameter. Before using the custom operator package, execute the source \$\{install_path\}/vendors/${vendor_name}_cv/bin/set_env.bash command. The set\_env.bash script appends the custom operator package installation path to the environment variable ASCEND\_CUSTOM\_OPP\_PATH so that the custom operator package takes effect in the current environment.

3. **(Optional) Uninstall the custom operator package.**

    After the custom operator package is installed, `uninstall.sh` is generated in the ```${ASCEND_HOME_PATH}/opp/vendors/${vendor_name}_cv/scripts``` directory. This script can uninstall the custom operator package. The command is as follows:

    ```bash
    bash ${ASCEND_HOME_PATH}/opp/vendors/${vendor_name}_cv/scripts/uninstall.sh
    ```

### ops-cv Package

> **Note**: Full compilation builds all operators in the repository and is time-consuming, depending on the machine configuration, the `-j` parallelism, and whether third-party dependencies are downloaded online. For daily development, prefer single-operator compilation (`--ops=<operator name>`).

1. **Compile the ops-cv package**

    Enter the project root directory and execute the following compile command:

    ```bash
    # Compile all operators except those in the experimental directory
    bash build.sh --pkg --soc=${soc_version} [-j${n}]
    # Compile all operators in the experimental directory
    # bash build.sh --pkg --experimental --soc=${soc_version} [-j${n}]
    ```

    - --soc: \$\{soc\_version\} indicates the NPU model. Atlas A2 products use "ascend910b" (default), Atlas A3 products use "ascend910_93", and Ascend 950PR&950DT products use "ascend950".
    - --experimental (optional): Indicates compiling the operators that the user stores under the experimental directory.
    - -j (optional): Specifies the number of compilation threads to speed up compilation.

    If the following information is displayed, the compilation is successful.

    ```bash
    Self-extractable archive "cann-${soc_name}-ops-cv_${cann_version}_linux-${arch}.run" successfully created.
    ```

    \$\{soc\_name\} indicates the NPU model name, that is, the remaining content after removing "ascend" from \$\{soc\_version\}. After successful compilation, the run package is stored in the build_out directory.

2. **Install the ops-cv package**

    ```bash
    # Installation command
    ./build_out/cann-${soc_name}-ops-cv_${cann_version}_linux-${arch}.run --full --install-path=${install_path}
    ```

    \$\{install\_path\}: indicates the specified installation path. It needs to be installed in the same path as the toolkit package. By default, it is installed in the `/usr/local/Ascend` directory.

3. **(Optional) Uninstall the ops-cv package**

    ```bash
    # Uninstall command
    "${install_path}/cann/share/info/ops_cv/script/uninstall.sh"
    ```

### ops-cv Static Library

> Note: The static library only supports Atlas A2 products, Atlas A3 products, and Ascend 950PR&950DT products. The experimental operators do not support the static library.

1. **Compile the ops-cv static library**

    Enter the project root directory and execute the following compile command:

    ```bash
    bash build.sh --pkg --static --soc=${soc_version} [-j${n}]
    ```

    - --soc: \$\{soc\_version\} indicates the NPU model. Atlas A2 products use "ascend910b" (default), Atlas A3 products use "ascend910_93", and Ascend 950PR&950DT products use "ascend950".
    - -j (optional): Specifies the number of compilation threads to speed up compilation.
    If the following information is prompted, the compilation and compression are successful.

    ```bash
    [SUCCESS] Build static lib success!
    Successfully created compressed package: ${repo_path}/build_out/cann-${soc_name}-ops-cv-static_${cann_version}_linux-${arch}.tar.gz
    ```

    \$\{repo\_path\} indicates the project root directory, and \$\{soc\_name\} indicates the NPU model name, that is, the remaining content after removing "ascend" from \$\{soc\_version\}. After successful compilation, the compressed package is stored in the build_out directory.

2. **Decompress the ops-cv static library**

    Enter the build_out directory and execute the decompression command:

    ```bash
    tar -zxvf ./cann-${soc_name}-ops-cv-static_${cann_version}_linux-${arch}.tar.gz -C ${static_lib_path}
    ```

    \$\{static\_lib\_path\} indicates the decompression path of the static library. The directory structure after decompression is as follows:

    ```bash
    ├── cann-${soc_name}-ops-cv-static_${cann_version}_linux-${arch}
    │   ├── lib64
    │   │   ├── libcann_cv_static.a                 # Static library file
    │   └── include
    |       ├── ...                                 # aclnn API header files
    ```

## Offline Compilation

If compilation is performed in an environment without internet access, prepare the dependent third-party software in advance, and then perform source code compilation. The specific process is as follows:

1. **Download third-party dependencies**

    Download third-party software in advance in an online environment. The following methods are available. Select one as needed:

    - Method 1: Manually download according to the table provided in [Install Third-Party Dependencies](#installing-third-party-dependencies). If downloading from another address, ensure the version number is consistent.

    - Method 2: Download with one click through the [third_lib_download.py](../../../scripts/tools/third_lib_download.py) script. The script is in the `scripts/tools/` directory of this project. Download the script and execute the following command:

        ```bash
        python ${scripts_dir}/third_lib_download.py
        ```

    \$\{scripts\_dir\} indicates the script storage path. The downloaded third-party software packages are stored by default in the directory where the current script is located.

2. **Compile the operator package**

    Upload the downloaded third-party software to the offline environment. It can be stored in the `third_party` directory or a custom directory. **The former is recommended, and its compile command is consistent with the command in the online compilation scenario.**

    - **third\_party directory **(recommended)**

    - **Custom directory**

        Create a `${cann_3rd_lib_path}` directory at any location in the offline environment, and copy the third-party software to this directory. Please ensure that this directory has access permission.

        ```bash
        mkdir -p ${cann_3rd_lib_path}
        ```

        At this point, the compile command needs to additionally add `--cann_3rd_lib_path=${cann_3rd_lib_path}` on the basis of the online compilation command to specify the path where the third-party software is located. Assuming the storage path is `/path/cann_3rd_lib_path`, the commands corresponding to different compilation methods are as follows:

        - Custom operator package

            ```bash
            bash build.sh --pkg --soc=${soc_version} [--vendor_name=${vendor_name}] [--ops=${op_list}] --cann_3rd_lib_path=${cann_3rd_lib_path}
            # Taking GridSample operator compilation as an example
            # bash build.sh --pkg --soc=ascend910b --ops=grid_sample -j16 --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```

        - ops-cv full package

            ```bash
            bash build.sh --pkg --soc=${soc_version} --cann_3rd_lib_path=${cann_3rd_lib_path}
            # bash build.sh --pkg --soc=ascend910b --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```

        - ops-cv static library

            ```bash
            bash build.sh --pkg --static --soc=${soc_version} --cann_3rd_lib_path=${cann_3rd_lib_path}
            # bash build.sh --pkg --static --soc=ascend910b --cann_3rd_lib_path=/path/cann_3rd_lib_path
            ```

3. **Install/uninstall the operator package**

    The operator packages obtained from offline and online compilation are the same. By default, they are stored in the build_out directory under the project root directory, and the install and uninstall commands are also the same. For details, see [Online Compilation](#online-compilation).

## Local Verification

After the source package is deployed, execute UT test cases through build.sh in the project root directory to verify whether the project functions work properly.

> Note: Executing UT test cases depends on the googletest unit test framework. For details, visit the [GoogleTest website](https://google.github.io/googletest/advanced.html#running-a-subset-of-the-tests).

```bash
# Install the test-related requirements.txt dependencies under the root directory
pip3 install -r tests/requirements.txt
# Method 1: Compile and execute the UT test cases of the specified operator and corresponding function (choose one)
bash build.sh -u --[opapi|ophost|opkernel|opkernel_aicpu] --ops=grid_sample
# Method 2: Compile and execute all UT test cases
# bash build.sh -u
# Method 3: Compile all UT test cases but not execute
# bash build.sh -u --noexec
# Method 4: Compile and execute the UT test cases of the corresponding function (choose one)
# bash build.sh -u --[opapi|ophost|opkernel|opkernel_aicpu]
# Method 5: Compile the UT test cases of the corresponding function but not execute (choose one)
# bash build.sh -u --noexec --[opapi|ophost|opkernel|opkernel_aicpu]
# Method 6: Specify soc compilation when executing UT test cases
# bash build.sh -u --[opapi|ophost|opkernel|opkernel_aicpu] [--soc=${soc_version}]
```

Take verifying whether the ophost function works properly as an example. Execute the following command:

```bash
bash build.sh -u --ophost
```

After execution, the following content appears, indicating successful execution.

```bash
Global Environment TearDown
[==========] ${n} tests from ${m} test suites ran. (${x} ms total)
[  PASSED  ] ${n} tests.
[100%] Built target cv_op_host_ut
```

\$\{n\} indicates that n test cases are executed, \$\{m\} indicates m tests, and \$\{x\} indicates the time consumed to execute the test cases, in milliseconds.

## FAQ

### Insufficient Permissions Error When Installing the Custom run Package

The default installation directory requires the current user to have read, write, and execute permissions. If prompted with insufficient permissions, choose one of the following methods:

- It is recommended to install to an absolute path writable by the current user, and load the environment variable script generated by the installation package:

    ```bash
    ./build_out/cann-ops-cv-*linux*.run --install-path=/absolute/path/to/opp
    source /absolute/path/to/opp/vendors/custom_cv/bin/set_env.bash
    ```

- If installation to the system CANN directory is required, use `sudo -E` to retain the currently configured CANN environment variables:

    ```bash
    sudo -E ./build_out/cann-ops-cv-*linux*.run
    ```

### Installing the Custom run Package Verifies the Dependency Library `libnnopbase.so`. When the Library Is Not in the Default Search Path, the Verification Fails and the Installation Is Interrupted

If the installation package exits only because the shared library dependency check fails, first confirm that the current CANN version is compatible with the build environment. After confirming compatibility, append `--force` to skip the shared library dependency check. Incorrect use of this parameter may cause operators to fail to load at runtime, so it is not recommended to use it by default.
